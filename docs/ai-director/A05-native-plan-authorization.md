## Security bug addressed

A01–A04 hashed the JavaScript draft in the frontend, while Rust's A03 Ledger accepted a caller-supplied `plan_hash` without independently recomputing the **same original typed plan**, including user instruction, exact editor project/session/version and all action parameters. This was a plan-substitution risk until a real native authorization path was implemented.

A05 implements a canonical, cross-language SHA-256 contract:
- `src/ai-director/plan-digest.mjs`: recursively lexical sorted keys, array order preserved, bounded structures and no non-finite numeric values or prototype tricks.
- `src-tauri/src/ai_director/src/plan.rs`: independent `serde_json` canonical hash; requires exactly `taskId`, `instruction`, `snapshot`, `actions`; parses every action into the Rust typed allowlist via `ipc::parse_action`. Confirms claimed project equals plan snapshot, validates plan hash, checks current exclusive native owner snapshot before ledger reservation. An unknown, stale or altered plan fails closed.
- `director.mjs`: includes the original instruction in review and sends the **complete validated immutable plan** to the journal's `reserve` method, not just a task ID, hash and project.
- `native-journal.mjs`: fixed `ai_director_reserve_plan` native IPC, requiring the native owner-bound durable receipt. Fixed `ai_director_record_audit` journal action with strict event allowlist and sanitized metadata. An informational `approved` audit event **cannot itself authorize** an edit. Missing/unregistered native commands block rather than simulate success.
- `guard.rs`: persists `instruction` in native Scope for actual owner review and prevents control characters in text. Rejects FilmCraft zero-frame trims before native command dispatch. It now REQUIRES `NativeOwner::preflight_action`: independent read-only native clip/layer/comp lookup before writing an irreversible step intent, then a second owner snapshot comparison. Missing objects reject without mutation, reservation replay, or uncertain state. The integration NativeOwner implementation must perform this preflight on the same native owner as manual edits.
- Exact bilingual cross-language SHA-256 vector for canonical plan:
  `3fbba55c9fb67a596487b13f556469770b59b40f4bf29b3fef51afb1a6cf6a40`. Both JavaScript and Rust tests assert it.
- `tests/ai-director-a05.test.mjs`: spoofed project, forged plan hash, changed instruction/action, missing native durable receipt and unapproved audit event tests.
- `src-tauri/src/ai_director/tests/native_guard.rs`: actual on-disk native owner-bound reservation/reopen, plan digest mismatch and stale native revision tests. Engine owners in tests are labelled TEST DOUBLES.

## Required integration for Chat 2.0.5

The integrated Windows host must **register** `ai_director_reserve_plan` with typed `ReserveWire`. It must hold the exact native editor owner's lock used by manual edits, call `ReserveWire::reserve(&Ledger,&mut owner)`, and return `{reserved:true, taskId, planHash, durable:true, nativeOwnerBound:true}` only after the native reservation and real disk persistence succeed. A success flag generated by a frontend mock is NOT sufficient.

`ai_director_record_audit` may record metadata only (never grant owner approval); the actual native approval flow must use `Ledger::approve` with a real owner-interaction gate, and each edit must use `Ledger::execute_bound` under the same native editor owner plus independent object readback. The user instruction should be visible in the owner approval display. No generic `invoke`, HTTP or shell proxy must be exposed to the model.

Ensure the integration native owner and JavaScript Director share **one task identity and plan hash** through both reservation and consent. JS-only approval can never replace the native approval claim. The A03 Ledger is file-based with Windows directory-entry power-loss durability limitations; a transactionally durable database and OS-private ACL verification remain required for production release.
